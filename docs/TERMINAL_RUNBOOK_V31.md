# VEYRA v3.1 — Terminal Runbook

## Purpose
Use this runbook when operating VEYRA managed security workers from a terminal. The terminal is a worker-local execution surface, not a SaaS shell.

## 1. Worker pre-flight

```bash
# Verify the host and VEYRA worker identity
hostname
id
uname -a

# Verify the selected tool is present
command -v <tool>
<tool> --version || <tool> --help
```

## 2. UI-first workflow

1. Sign in as the appropriate VEYRA role.
2. Open **Sudo Security Arsenal**.
3. Select the tool and review its purpose/help.
4. Select an asset/scope that is explicitly authorized.
5. Enter purpose and approval/ticket context.
6. Review the signed job contract.
7. Queue the job to the isolated managed worker.
8. Review normalized evidence, timestamps, tool version and hashes.
9. Map validated findings to the Security Graph, ATT&CK/ATLAS, remediation and verification.

## 3. Terminal workflow

```bash
# Always begin with help/version on the enrolled worker
sudo -n <tool> --help

# Then use ONLY the command profile generated by VEYRA for the approved scope.
# Capture stdout/stderr and exit status for evidence.
```

The platform should never accept an arbitrary shell command from a browser field. Tool parameters are represented as typed forms and validated before a worker contract is created.

## 4. Evidence capture
Capture:
- tool name/version
- worker identity
- job/contract ID
- target scope
- start/end timestamps
- stdout/stderr or structured output
- artifact hashes
- SBOM/provenance references
- operator and approval identity

## 5. Privileged tools
Privileged tools require the Sudo/privileged-admin policy. Production deployment should add SSO, MFA, PAM, short-lived credentials and just-in-time capability leases.

## 6. Incident investigation
Use **Adversary Trace** rather than counter-intrusion. Preserve evidence, correlate network/endpoint/identity/cloud telemetry, enrich indicators, reconstruct the timeline, create containment options and preserve an auditable evidence bundle.

## 7. Prohibited terminal behavior
- no hack-back
- no unauthorized target testing
- no payload delivery or persistence
- no C2 deployment
- no credential theft
- no destructive/disruptive commands
- no bypass of VEYRA scope/approval controls
