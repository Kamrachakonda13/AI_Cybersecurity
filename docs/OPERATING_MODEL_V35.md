# VEYRA v3.5 Operating Model

VEYRA is organized around outcomes rather than a flat list of tools.

1. **Discover** — establish authoritative inventory.
2. **Understand** — establish ownership, criticality and expected behavior.
3. **Validate** — test controls with authorized workers.
4. **Investigate** — preserve evidence and reconstruct events.
5. **Correlate** — connect telemetry into the Security Graph.
6. **Contain** — stage bounded, approved defensive actions.
7. **Recover** — restore trusted state and verify it.
8. **Prove** — preserve hashes, provenance and audit evidence.
9. **Learn** — improve detections, controls, playbooks and training.
10. **Continuously revalidate** — repeat the checks and detect drift.

## Team usage

Use the lifecycle view as the daily navigation layer. Use the Tool Academy for learning. Use Sudo Security Arsenal for governed tool selection. Use Adversary Trace and Security Graph for investigations. Use Continuous Validation for recurring control checks.

## Definition of done

A security issue is not considered closed merely because a scanner says `fixed`. VEYRA should have remediation evidence, recovery verification, proof/provenance, and a subsequent revalidation result.
