Request flow

Client query
→
Router (intent)
→
Hybrid retrieval (vector + BM25 + RRF)
→
Cross-encoder rerank
→
Confidence gate (score + coverage)
→
Groq LLM (grounded)
→
Audit log

The confidence gate is terminal — a refusal stops the loop instead of allowing the agent to find a way to answer.

Component map

Component Role Why this choice
pgvector Vector store with HNSW index SQL filtering lets ACLs be enforced at query time, not post-retrieval
Neo4j 5.24 Entity graph for relationship queries Multi-hop traversal is a graph operation, not a vector one
Groq gpt-oss-20b Grounded generation Free tier, fast, adequate for grounded answers
MiniLM-L6-v2 Embeddings (384-dim, local) Zero cost, no API dependency for a baseline
MinIO S3-compatible object store Real S3 interface without cloud dependencies
FastAPI API + HTML dashboard Same service serves /ask, /admin/*, and /dashboard/*
Docker Compose Four-container stack Reproducible: postgres, neo4j, minio, api

Design trade-offs

Decision Choice Alternative Reason
Chunk size 400 / 50 overlap Sentence or document Balances context preservation with embedding focus
Vector store pgvector + HNSW FAISS Persistence and SQL filtering; simpler ops
ACL enforcement At query (SQL WHERE) Post-retrieval filter Unauthorized content never enters the retrieval layer
Refusal Terminal, on confidence failure Best-effort answer In security, a hallucinated mitigation is worse than no answer
Retrieval merge RRF (k=60) Score averaging Rank-based fusion is robust to score-scale mismatch
